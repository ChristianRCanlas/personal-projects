GitHub actually renders Jupyter notebooks natively, so the "trick" portfolio repos use is simpler than it looks — 
they're just making sure the image data is saved inside the notebook file itself before pushing it.

**How it works under the hood**

A `.ipynb` file is JSON. When you run a cell that produces a matplotlib plot, Jupyter captures the rendered 
image as a base64-encoded PNG and stores it in that cell's `outputs` field, right alongside the code. 
When you push the notebook to GitHub, GitHub's notebook renderer reads that JSON and displays the embedded 
image — no separate image files needed, no rendering step on GitHub's end.

**Steps to replicate it**

1. **Run the notebook top to bottom** (Kernel → Restart & Run All, or `jupyter nbconvert --execute`) so 
every cell's output — including plots — is actually generated and attached.
2. **Save the notebook** after running it. This writes the image data into the `.ipynb` file.
3. **Commit and push the `.ipynb` file itself** (not just the `.py` source or a cleared version). 
Don't run `nbstripout` or "clear all outputs" before committing, or the images disappear.
4. GitHub will render it automatically on the repo page — just click the file.

**A few practical notes**

- File size: embedded PNGs bloat the notebook file since they're base64 text. For a portfolio with 
lots of plots this can make repos heavy — usually fine, just worth knowing.
- If a notebook is too large or complex and GitHub's renderer times out or shows 
"Sorry, something went wrong," people often link to it via [nbviewer](https://nbviewer.org/) 
instead, which renders more reliably and handles bigger files.
- If you want a plot to show up in your **README** (not inside a notebook), that's different — 
you'd export it explicitly with `plt.savefig("plot.png")`, commit the PNG, and reference it with standard markdown: `![description](plot.png)`.
- Set `plt.tight_layout()` and a reasonable `dpi` (100–150) in `savefig`
/before display so images look clean on GitHub's rendering rather than cramped or blurry.

So the short version: run the notebook, save it with outputs intact, push the `.ipynb` as-is. GitHub does the rest.
